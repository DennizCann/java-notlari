Metotlar ve OOP ile kurduğumuz temeli şimdi kullanıcı girdisi, hata yönetimi, dosyalar ve Java’nın hazır araçlarıyla tamamlayacağız. Bu bölüm, temel kursun son bölümüdür; Java’nın bütün uzmanlık alanlarını kapsamaz.

Örnekler Java 21 ile hazırlanmıştır. Her kod kutusunu ayrı bir Main.java dosyası olarak çalıştırabilirsin. import, hazır bir tipi kısa adıyla kullanmamızı sağlar; kütüphane indirme komutu değildir. Buradaki API’ler JDK içinde gelir.

7.1 Kullanıcı Girdisi: Scanner

Scanner metin girdisini okur. System.in klavyeden gelen standart girdidir. next() boşlukla ayrılan bir parçayı, nextLine() satırın kalanını, nextInt() tam sayı okur.

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        try (Scanner input = new Scanner(System.in)) {
            System.out.println("Yaşınızı yazın:");
            int age = input.nextInt();
            input.nextLine(); // Sayıdan sonra kalan satır sonunu tüket.
            System.out.println("Adınızı yazın:");
            String name = input.nextLine();
            System.out.println(name + ": " + age);
        }
    }
}

Örnek giriş: 25 / Deniz · Çıktı:

Yaşınızı yazın:
Adınızı yazın:
Deniz: 25

nextInt ile nextLine neden karışır?

nextInt() sayıyı okur, satır sonunu tüketmez. Hemen ardından gelen nextLine() bu yüzden boş metin döndürebilir. Örnekte araya bir nextLine() koyarak satırın kalanını tükettik. Diğer yaklaşım bütün girdileri satır olarak okuyup Integer.parseInt(input.nextLine()) ile dönüştürmektir.

Sayı yerine metin girilirse nextInt(), InputMismatchException üretir. Öncesinde hasNextInt() ile kontrol edebilirsin; geçersiz girdiyi bir döngüde yeniden sorarken tüketmeyi unutma. Ondalıklı sayı okuma biçimi Scanner’ın yerel ayarına bağlıdır.

Örnekte program biterken Scanner kapanır; bu, bağlı olduğu System.in akışını da kapatır. Daha uzun programlarda aynı girdi kaynağını paylaş, okumaya devam edeceksen erken kapatma. try (...) yapısını dosyalar konusunda açıklayacağız.

7.2 Hata Yönetimi: Exceptions

Exception, bir işlem normal biçimde tamamlanamadığında oluşan nesnedir. Hatalı sayı dönüşümü veya bulunamayan dosya buna örnektir. try denenmek istenen işlemi, catch belirli hataya verilecek yanıtı içerir.

public class Main {
    public static void main(String[] args) {
        try {
            int age = Integer.parseInt("yirmi");
            System.out.println(age);
        } catch (NumberFormatException e) {
            System.out.println("Geçerli bir tam sayı girin.");
        } finally {
            System.out.println("Deneme tamamlandı.");
        }
    }
}

Çıktı:

Geçerli bir tam sayı girin.
Deneme tamamlandı.

Hata oluştuğunda try bloğunun kalan kısmı atlanır ve uygun catch aranır. finally normal akışta hata olsa da olmasa da çalışır; JVM’nin sonlandırılması gibi durumlarda çalışma garantisi yoktur. Kaynak kapatma için çoğunlukla try-with-resources kullanılır. Hataları boş catch ile sessizce yutma.

Checked, unchecked, throw ve throws

Checked exception için derleyici, hatayı yakalamanı veya metodun throws bildirimine eklemeni ister; IOException buna örnektir. Unchecked exception, RuntimeException ve alt tipleridir; örneğin IllegalArgumentException. Bunlarda bu derleme zorunluluğu yoktur. Error türleri ise genellikle sıradan kullanıcı hatası gibi ele alınmaz.

throw belirli bir hata nesnesini fırlatır. throws metodun hangi hatayı çağırana aktarabileceğini bildirir; hatayı çözmez. Birden çok catch kullanırsan özel alt tipleri genel tiplerden önce yazmalısın.

class InvalidScoreException extends Exception {
    InvalidScoreException(String message) {
        super(message);
    }
}

public class Main {
    static void checkScore(int score) throws InvalidScoreException {
        if (score < 0 || score > 100) {
            throw new InvalidScoreException("Puan 0–100 arasında olmalı.");
        }
    }

    public static void main(String[] args) {
        try {
            checkScore(120);
        } catch (InvalidScoreException e) {
            System.out.println(e.getMessage());
        }
    }
}

Çıktı:

Puan 0–100 arasında olmalı.

Kendi hata tipimiz Exception’dan türediği için checked’dır. Her kontrol için özel sınıf gerekmez; geçersiz bir metot argümanı için hazır IllegalArgumentException da uygundur.

7.3 Dosyalar ve I/O

I/O, girdi ve çıktı işlemleridir. Path bir dosya veya klasör yolunu temsil eder; tek başına dosya oluşturmaz. Files dosyayı okuma, yazma, kopyalama ve silme gibi işlemler sunar. Göreli yollar programın çalışma klasörüne göre çözülür.

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

public class Main {
    public static void main(String[] args) {
        try {
            Path file = Files.createTempFile("java-notlari-", ".txt");
            try {
                Files.writeString(file, "Merhaba Java!", StandardCharsets.UTF_8);
                String text = Files.readString(file, StandardCharsets.UTF_8);
                System.out.println(text);
            } finally {
                Files.deleteIfExists(file);
            }
        } catch (IOException e) {
            System.out.println("Dosya işlemi başarısız: " + e.getMessage());
        }
    }
}

Çıktı:

Merhaba Java!

Örnek geçici bir dosya oluşturur, UTF-8 metin yazar, okur ve temizler. Kalıcı bir dosya için Path.of("notlar.txt") kullanılabilir. writeString varsayılan olarak mevcut içeriğin üzerine yazar; ekleme için StandardOpenOption.CREATE ve StandardOpenOption.APPEND seçenekleri verilebilir.

Byte akışı, karakter akışı ve kaynak kapatma

InputStream / OutputStream byte verisiyle çalışır; resim ve PDF gibi ikili dosyalarda kullanılır. Reader / Writer karakterlerle çalışır; metni byte’a çevirirken UTF-8 gibi bir kodlama devreye girer. BufferedReader ve BufferedWriter, işlemleri tamponlayarak küçük okuma/yazmaları biriktirir.

import java.io.BufferedReader;
import java.io.IOException;
import java.io.StringReader;

public class Main {
    public static void main(String[] args) {
        try (BufferedReader reader = new BufferedReader(
                new StringReader("Java\nOOP"))) {
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        } catch (IOException e) {
            System.out.println("Okuma başarısız.");
        }
    }
}

Çıktı:

Java
OOP

Bu örnekte dosya yerine bellekteki metni okuduk. Dosyada aynı döngü Files.newBufferedReader(path, StandardCharsets.UTF_8) ile kullanılabilir. readLine() dosya sonunda null döndürür; boş satır ise boş String’dir.

Try-with-resources, parantezde oluşturulan AutoCloseable kaynakları blok sonunda hata olsa bile kapatır. Birden fazla kaynak ters sırayla kapatılır. readString bütün içeriği belleğe alır; büyük metinlerde satır satır okumak daha uygundur. Buradaki I/O akışları, 5. bölümdeki koleksiyonları işleyen Stream API ile aynı kavram değildir.

7.4 Generics

Generics, bir sınıf veya metodun çalışacağı türü parametre yapar. List<String> bunun tanıdık örneğidir. Yanlış türlerin eklenmesini derleme sırasında yakalar ve gereksiz cast işlemlerini azaltır.

class Box<T> {
    private final T value;

    Box(T value) {
        this.value = value;
    }

    T get() {
        return value;
    }
}

public class Main {
    static <T> T first(T[] items) {
        if (items.length == 0) {
            throw new IllegalArgumentException("Dizi boş olamaz.");
        }
        return items[0];
    }

    public static void main(String[] args) {
        Box<String> box = new Box<>("Java");
        System.out.println(box.get());
        System.out.println(first(new Integer[]{10, 20}));
    }
}

Çıktı:

Java
10

T bir tür parametresidir; adı zorunlu olarak T olmak zorunda değildir. Generic metotta <T> dönüş tipinden önce gelir. <> ile derleyici türü bağlamdan çıkarır. Primitive yerine wrapper kullanılır: Box<Integer> geçerlidir, Box<int> değildir.

Bounds ve wildcard

<T extends Number>, kabul edilen türleri Number ve alt tipleriyle sınırlar. ? ise türü bilinmeyen bir parametreyi gösterir. List<Integer>, List<Number>’ın alt tipi değildir; bu nedenle ortak okuma işlemlerinde wildcard kullanırız.

import java.util.ArrayList;
import java.util.List;

public class Main {
    static double total(List<? extends Number> numbers) {
        double result = 0;
        for (Number number : numbers) {
            result += number.doubleValue();
        }
        return result;
    }

    static void addOne(List<? super Integer> numbers) {
        numbers.add(1);
    }

    public static void main(String[] args) {
        System.out.println(total(List.of(10, 20)));
        List<Number> numbers = new ArrayList<>();
        addOne(numbers);
        System.out.println(numbers);
    }
}

Çıktı:

30.0
[1]

? extends Number ile Number olarak okuyabiliriz; gerçek alt tür bilinmediği için null dışında eleman ekleyemeyiz. ? super Integer ile Integer ekleyebiliriz, fakat okunan elemanın garantili tipi Object’tir. Ham List kullanmak tür kontrolünü zayıflatır; tür parametresini belirt.

7.5 Nesneleri Sıralama: Comparable ve Comparator

Sayı ve String sıralamasını gördük. Kendi sınıfımızın nesnelerinde hangi ölçütün kullanılacağını belirtmemiz gerekir. Comparable sınıfın doğal sırasını, Comparator dışarıdan seçilen sıralama ölçütünü tanımlar.

import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Student implements Comparable<Student> {
    final String name;
    final int score;

    Student(String name, int score) {
        this.name = name;
        this.score = score;
    }

    @Override
    public int compareTo(Student other) {
        return name.compareTo(other.name);
    }

    @Override
    public String toString() {
        return name + ":" + score;
    }
}

public class Main {
    public static void main(String[] args) {
        List<Student> students = new ArrayList<>(List.of(
            new Student("Deniz", 80), new Student("Ece", 95)));
        System.out.println(students.stream().sorted().toList());
        Comparator<Student> byScore = Comparator
            .comparingInt((Student s) -> s.score).reversed()
            .thenComparing(s -> s.name);
        students.sort(byScore);
        System.out.println(students);
    }
}

Çıktı:

[Deniz:80, Ece:95]
[Ece:95, Deniz:80]

compareTo sonucu negatifse önce, sıfırsa aynı sıra düzeyinde, pozitifse sonra gelir; yalnızca −1, 0, 1 dönmesi gerekmez. Sayısal karşılaştırmada çıkarma yerine Integer.compare(a, b) taşma riskini önler.

reversed() puan sırasını ters çevirir; thenComparing eşit puanları ada göre sıralar. List.sort listeyi değiştirir. stream().sorted(byScore).toList() ise kaynak listeyi değiştirmeden sonuç üretir.

Örnek doğal sırayı yalnızca ada göre tanımlar; aynı adlı iki öğrenci karşılaştırmada 0 verebilir. TreeSet ve TreeMap bunu aynı sıra anahtarı olarak ele alır. Bu yapılarda beklenen küme/harita davranışı için sıralama ile equals tutarlı tasarlanmalıdır; burada yalnızca List sıralıyoruz.

7.6 Yardımcı API’ler

Tarih ve saat

LocalDate tarih, LocalTime saat, LocalDateTime tarih ve saat tutar; saat dilimi içermezler. Bir anı zaman çizgisinde tutmak için Instant, saat dilimiyle birlikte göstermek için ZonedDateTime kullanılır. Bu türler değişmezdir; plusDays gibi işlemler yeni değer döndürür.

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;

public class Main {
    public static void main(String[] args) {
        LocalDate start = LocalDate.of(2026, 9, 24);
        LocalDate end = start.plusDays(7);
        DateTimeFormatter format = DateTimeFormatter.ofPattern("dd.MM.yyyy");
        System.out.println(end.format(format));
        System.out.println(ChronoUnit.DAYS.between(start, end));
    }
}

Çıktı:

01.10.2026
7

Bugünün tarihi için LocalDate.now(), ISO biçimindeki metni okumak için LocalDate.parse("2026-09-24") kullanılabilir. Örnekte sonuç sabit olsun diye tarihi açıkça verdik.

Math, rastgele sayılar, StringBuilder ve regex

Math hazır matematik işlemleri sunar. Random.nextInt(6), 0 dahil 6 hariç sayı üretir; 1 ekleyerek zar aralığına ulaşırız. Güvenlik amacıyla gereken rastgele değerlerde SecureRandom kullanılır.

String değişmezdir. StringBuilder, özellikle döngüde metni parça parça oluşturmak için değiştirilebilir bir yapı sunar. append ekler, toString sonucu String’e çevirir. Regex, metindeki örüntüleri tanımlar; matches bütün metni kontrol eder, Matcher’ın find() metodu ise eşleşen parçaları arar.

import java.util.Random;

public class Main {
    public static void main(String[] args) {
        System.out.println(Math.max(10, 25));
        System.out.println(Math.sqrt(81));
        int dice = new Random().nextInt(6) + 1;
        System.out.println(dice >= 1 && dice <= 6);
        StringBuilder text = new StringBuilder("Java");
        text.append(" ").append("Notları");
        System.out.println(text.toString());
        System.out.println("1234".matches("\\d{4}"));
    }
}

Çıktı:

25
9.0
true
Java Notları
true

Regex’te \d rakamı, {4} dört tekrarı belirtir. Java String’inde ters eğik çizgi de kaçırıldığı için kodda "\\d{4}" yazarız. Rastgele sayının kendisi değişse de örnekteki aralık kontrolü her zaman true’dur. Sık kullanılan karmaşık bir örüntü için Pattern.compile ile Pattern oluşturup tekrar kullanabiliriz.

7.7 Eşzamanlı Çalışmaya Giriş

Thread, program içindeki bir yürütme akışıdır. Birden fazla iş ilerleyebilir; ancak bu, her zaman fiziksel olarak aynı anda çalıştıkları anlamına gelmez. Runnable yapılacak işi, Thread bu işin çalışacağı akışı temsil eder.

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> System.out.println("İş tamamlandı.");
        Thread worker = new Thread(task);
        worker.start();
        worker.join();
        System.out.println("Ana akış devam ediyor.");
    }
}

Çıktı:

İş tamamlandı.
Ana akış devam ediyor.

start() yeni akışı başlatır. Doğrudan run() çağırmak işi mevcut akışta yürütür. join(), worker bitene kadar çağıran akışı bekletir; bu yüzden örnekte çıktı sırası bellidir. Bekleme kesilirse InterruptedException oluşabilir; örnekte main bunu throws ile bildirir.

Paylaşılan veriye dikkat

İki thread aynı değişkeni değiştirirse race condition oluşabilir. count++ tek ve bölünmez bir işlem değildir. Kritik bölgeyi aynı kilitle synchronized kullanarak koruyabilir veya sayaç için AtomicInteger.incrementAndGet() seçebiliriz. volatile tek başına count++ işlemini atomik yapmaz.

Thread.sleep bir eşgüdüm garantisi sağlamaz. Çok sayıda işte her iş için elle thread yönetmek yerine ExecutorService gibi araçlar kullanılabilir. Şimdilik işi tanımlama, başlatma, bekleme ve ortak veriyi koruma ayrımını bilmek yeterli.

Soru — Cevap

Soru: nextInt sonrasında nextLine neden boş dönebilir?

Cevap: Sayı okunduktan sonra satır sonu girdide kalır; nextLine satırın kalanını okur.

Soru: throw ile throws aynı mı?

Cevap: Hayır. throw hata nesnesini fırlatır; throws metodun aktarabileceği hata tipini bildirir.

Soru: Path.of dosya oluşturur mu?

Cevap: Hayır. Yolu temsil eder; dosya oluşturma ve yazma ayrı işlemlerdir.

Soru: Try-with-resources neyi kolaylaştırır?

Cevap: AutoCloseable kaynakların bloktan çıkılırken kapatılmasını.

Soru: Dosya akışı ile Stream API aynı şey mi?

Cevap: Hayır. I/O akışları veri okuma/yazma, Stream API ise elemanlar üzerinde işlem hattı kurma amacı taşır.

Soru: List<Integer>, List<Number> yerine doğrudan verilir mi?

Cevap: Hayır. Yalnızca okuma gereken uygun bir metot List<? extends Number> kabul edebilir.

Soru: Comparable ve Comparator ne zaman kullanılır?

Cevap: Comparable doğal sıra için; Comparator farklı veya dışarıdan belirlenen sıralama ölçütleri için.

Soru: LocalDate.plusDays mevcut tarihi değiştirir mi?

Cevap: Hayır. Yeni bir LocalDate döndürür; sonucu kullanmak veya atamak gerekir.

Soru: Thread.run yeni thread başlatır mı?

Cevap: Hayır. Yeni yürütme akışı için start kullanılır.

Soru: count++ birden fazla thread için güvenli mi?

Cevap: Ortak değiştirilebilir sayaçta tek başına güvenli değildir; uygun eşgüdüm gerekir.
